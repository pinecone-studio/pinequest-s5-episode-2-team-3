# Дусал — 2-р хэсэг: Ус бүртгэх

Багийн 4 хэсгээс зөвхөн **ус бүртгэх** хэсгийг үлдээсэн вэб. Монгол интерфейстэй, утасны хэрэглээнд төвлөрсөн загвартай. Утсанд бүртгэх товч доор тогтмол байрлана; дарах талбай 44–52px, оруулах цонх доороос нээгдэж гүйлгэнэ. Компьютерт мөн ажиллана.

## Ажиллуулах

```sh
bun install
bun run dev
```

Терминалд гарсан локал хаягийг нээнэ (ихэвчлэн http://127.0.0.1:5173). Сервер ажиллаж байх үед вэб нээгдэнэ.

```sh
bun run typecheck
bun run build
bun run preview
```

## Энэ хэсгийн ажил

- Усны хэмжээ бүртгэх; анхдагч төрөл нь «Уусан»
- +150 / +250 / +500 мл хурдан нэмэх
- Уусан ↔ асгасан шууд өөрчлөх
- Хэмжээ, төрөл, огноо, цаг засах
- Тодорхойгүй бүртгэлийг уусан / асгасан гэж шийдэх
- Устгах; сүүлийн нэмэлт, засвар, төрөл солих, устгах үйлдлийг 10 секундын дотор буцаах
- Бүртгэлээ жагсаалтаас нээж засах

Өдрийн тойм, зорилт, график (1), түүхийн шүүлтүүр / CSV (3), hardware холболт ороогүй.

## 4-р хэсэг: Тохиргоо ба нөөц (`/settings.html`)

- Өдрийн зорилт эсвэл дээд хязгаар (50–10,000 мл) тохируулах, 10 секундын дотор буцаах
- Бүртгэл, тохиргоо `localStorage`-ийн `dusal-v1` түлхүүрт хадгалагдаж, вэбийг дахин нээхэд сэргэнэ
- Бүх мэдээллийг `dusal-backup-ОООО-СС-ӨӨ.json` файл болгон татах
- Нөөц файлыг шалгаж (5 MB хүртэл, JSON, бүтэц, давхардсан id), харьцуулалтыг харуулаад, баталгаажуулсны дараа сэргээх; сэргээснээ буцааж болно
- Хадгалалт бүтэлгүйтвэл, өгөгдөл эвдэрсэн бол, эсвэл өөр цонхонд өөрчлөгдсөн бол мэдэгдэнэ; хуучин мэдээллээр дарж бичихгүй. Эвдэрсэн өгөгдлийг зөвхөн нөөцөөс сэргээх үед, баталгаажуулсны дараа солино

Код: `src/storage.ts` (унших/бичих, олон цонхны зөрчил), `src/backup.ts` (татах, шалгах), `src/settings.ts`, `src/settings.css`.

## Кодын хуваарь

- `src/main.ts` — програм эхлүүлэх, stylesheet ачаалах
- `src/app.ts` — state, хадгалалт, бүртгэлийн үйлдлүүдийг component-уудтай холбох
- `src/components/EntryPage.ts` — үндсэн дэлгэцийн бүтэц
- `src/components/EntryList.ts` — бүртгэлийн мөрүүд, засах/төрөл солих товчлуурууд
- `src/components/EntryDialog.ts` — оруулах/засах цонх, form validation
- `src/components/Toast.ts` — мэдэгдэл, үйлдэл буцаах товч, хугацаа
- `src/components/Icon.ts` — SVG тэмдэг
- `src/data.ts` — өгөгдлийн төрөл, validation, огноо, эрэмбэлэлт
- `src/format.ts` — тоо/цаг/огноо/текстийн формат
- `src/style.css` — responsive загвар

Component-ууд нь TypeScript функцүүд; нэмэлт UI framework ашиглахгүй. Дэлгэц нь хадгалалтын кодыг шууд өөрчлөхгүй, callback-аар `app.ts`-д үйлдлээ дамжуулна.

Бие даан ажиллахад хэрэгтэй localStorage хадгалалтыг үлдээсэн. Өмнөх `dusal-v1` өгөгдөл болон `goal`, `mode` талбарыг нийцтэй байлгахын тулд хадгална; энэ хэсэг тэдгээрийг өөрчлөхгүй. Нэвтрэлт, сервер, төхөөрөмж хоорондын синк байхгүй. Браузерын өгөгдлөө цэвэрлэвэл бүртгэл арилна.

Хэмжээ 1–5,000 мл бүхэл тоо байна. Ирээдүйн огноо оруулахгүй. Хадгалалт бүтэлгүйтвэл өөрчлөлтийг амжилттай гэж үзэхгүй. Уншигдахгүй хуучин өгөгдлийг автоматаар дарж бичихгүй. Өөр цонхны шинэчлэлийг хуучин өгөгдлөөр дарахаас хамгаална.

## Cloudflare-д deploy хийх

Вэб (`dusal`) болон API (`dusal-api`) нь тусдаа Worker. Тохиргоо нь `wrangler.jsonc` файлд.

```sh
npx wrangler login            # нэг удаа
bun run deploy                # вэб: build → ./dist-ийг static assets болгон upload
cd backend && npm run db:migrate:remote && npm run deploy   # API + D1
```

Анхаарах: бүртгэл localStorage-д хадгалагддаг тул домэйн бүр (preview хаяг ч гэсэн) тусдаа өгөгдөлтэй. Хэрэглэгчдэд нэг үндсэн хаяг өгнө.

### Автомат deploy (GitHub Actions)

`main` руу код орох бүрт `.github/workflows/deploy.yml` нь вэб болон API-г автоматаар deploy хийнэ. API-гийн өмнө D1 migration-уудыг хийнэ. PR дээр зөвхөн build-ыг шалгана. Ажиллахын тулд repo-д дараах secret-үүд хэрэгтэй (Settings → Secrets and variables → Actions):

| Secret | Утга |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare account ID |
| `CLOUDFLARE_API_TOKEN` | «Edit Cloudflare Workers» загвараар үүсгэсэн token, дээр нь **D1: Edit** эрх нэмнэ |
